# filament-storage Specification

## Purpose
How filaments and tags are stored: which values the database accepts, how soft-deleted filaments are hidden by default, and how the full-text search vector (title A, body B, `english` config) is kept current by Postgres.
## Requirements
### Requirement: Filaments store a title, body, source and timestamps
The system SHALL store each filament with a UUID id, a `title` of at most 200 characters, a Markdown `body`, a `source` of `claude` or `web`, `created_at`, `updated_at`, and a nullable `deleted_at`. The id SHALL be generated by the system. `created_at` SHALL be set on insert, and `updated_at` on every save.

#### Scenario: Filament created by Claude
- **WHEN** a filament is saved with title "Album cover ideas", body "Matte sleeve, hand-drawn type" and source `claude`
- **THEN** it is stored with a generated UUID id, `created_at` and `updated_at` set to the current time, and `deleted_at` empty

#### Scenario: Title too long
- **WHEN** a filament is saved with a 201-character title
- **THEN** the database rejects the write

### Requirement: Title and body are required
The database SHALL reject a filament whose `title` or `body` is empty or contains only whitespace.

#### Scenario: Empty body
- **WHEN** a filament is saved with title "Buy olive oil" and an empty body
- **THEN** the database rejects the write with an integrity error

#### Scenario: Whitespace-only title
- **WHEN** a filament is saved with title "   " and a non-empty body
- **THEN** the database rejects the write with an integrity error

### Requirement: Source must be a known value
The database SHALL reject a filament whose `source` is anything other than `claude` or `web`, and SHALL NOT supply a default.

#### Scenario: Unknown source
- **WHEN** a filament is saved with source `email`
- **THEN** the database rejects the write with an integrity error

### Requirement: Tags are unique, lowercase and contain no whitespace
The system SHALL store each tag name once. The database SHALL reject a tag name that is empty, contains uppercase letters, contains whitespace, or is longer than 50 characters. A filament SHALL relate to any number of tags through a many-to-many relation; the 8-tag limit is enforced before writes reach the database (step 3).

#### Scenario: Duplicate tag name
- **WHEN** a tag `music` already exists and another tag `music` is inserted
- **THEN** the database rejects the second insert

#### Scenario: Unnormalized tag reaches the database
- **WHEN** a tag named `Music` or `album art` is inserted directly
- **THEN** the database rejects the write with an integrity error

#### Scenario: Tag shared by filaments
- **WHEN** two filaments are both tagged `music`
- **THEN** a single `music` tag row exists and `tag.filaments` returns both filaments

### Requirement: Soft-deleted filaments are hidden by default
The default way of querying filaments SHALL exclude rows where `deleted_at` is set, including when filaments are reached through a tag. An explicit unfiltered query SHALL still return them. Soft-deleting a filament SHALL set `deleted_at` to the current time and leave the row in place.

#### Scenario: Soft delete hides a filament
- **WHEN** a filament is soft-deleted
- **THEN** it no longer appears in the default filament query or in `tag.filaments` for any of its tags
- **AND** it still appears in the unfiltered (`all_objects`) query with `deleted_at` set

#### Scenario: Deleted filament still visible in admin
- **WHEN** the admin filament list is opened after a soft delete
- **THEN** the deleted filament is listed and can be filtered by whether it is deleted

### Requirement: Search vector stays current with title and body
Each filament SHALL have a full-text `search_vector`, computed by the database from `title` (weight A) and `body` (weight B) using the `english` text-search configuration, with a GIN index. It SHALL update whenever `title` or `body` changes, however the row is written. Tags SHALL NOT be part of the vector.

#### Scenario: Stemmed match on body
- **WHEN** a filament with body "I went for a run by the river" is saved and searched with the `english` query "running"
- **THEN** the filament matches

#### Scenario: Title outranks body
- **WHEN** filament A has "harmony" in its title and filament B has "harmony" only in its body
- **THEN** ranking by the search vector for "harmony" puts A before B

#### Scenario: Vector follows a bulk update
- **WHEN** a filament's body is changed with a queryset `update()` (bypassing `save()`)
- **THEN** a search for a word in the new body matches it, and a search for a word only in the old body does not

#### Scenario: Tag names are not in the vector
- **WHEN** a filament tagged `music` never mentions "music" in its title or body
- **THEN** a search-vector query for "music" does not match it (tag matching for keyword search is added in step 5)

### Requirement: Dates use the configured home timezone
The system SHALL store timestamps in UTC and SHALL use a home timezone, set by `FILAMENTS_TIMEZONE` (an IANA name such as `America/Chicago`, default `UTC`), as Django's current timezone. Calendar dates such as "today" SHALL be computed in that timezone. An unknown timezone name SHALL stop the app at startup with a clear error.

#### Scenario: Late-evening note counts as the local day
- **WHEN** `FILAMENTS_TIMEZONE` is `America/Chicago` and a filament is created at 2026-11-24 23:30 Chicago time (05:30 UTC on 2026-11-25)
- **THEN** it is stored with a UTC `created_at`, and its local date is 2026-11-24

#### Scenario: Unknown timezone
- **WHEN** `FILAMENTS_TIMEZONE` is `America/Chicagoo`
- **THEN** startup fails with an error naming the bad setting
